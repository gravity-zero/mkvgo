# Changelog 0.60 to 0.69

Archived entries of mkvgo 0.60.x to 0.69.x, as they were published; a version moves here once a newer one ships. The current versions are in [CHANGELOG.md](../CHANGELOG.md).

## [0.66.0] - 2026-11-08

### Breaking

- `demux` of a Matroska/WebM writes five more codecs in the file their tools
  read, where it wrote the bare payloads under the codec's name: AV1 as a
  low-overhead OBU stream with a temporal delimiter a temporal unit (`.obu`;
  was `.av1`, which a decoder read as no frame at all), VP8 and VP9 in IVF
  (`.ivf`; were `.vp8`, `.vp9`), MPEG-4 Part 2 behind its VOS/VOL headers
  (`.m4v`; was `.mpeg4`), ALAC in CAF with its magic cookie and packet table
  (`.caf`; was `.alac`), PCM in WAV (`.wav`; was `.pcm`, or the sample format
  such as `.pcm_f64le`; big-endian samples turned little-endian). `--raw`
  (`DemuxOptions.Raw`) still writes the former files, names included.
- `mp4.DroppedTrack` is now an alias of `mkv.DroppedTrack`, the one struct both
  directions report through (gorelease lists the type and every signature
  carrying it as changed; source that names `mp4.DroppedTrack` compiles as it
  is, the two being one type).

### Changed

- The `dropped track N (codec): reason` lines of `to-mp4`, `from-mp4`,
  `to-hls` (and `to-abr`, `concat-hls`), `split`, `join`, `mux`, `merge` and
  `merge-subtitle` go to stderr, no longer stdout, like those of `serve`,
  `demux` and the segment commands: stdout keeps the command's result alone.
  `--strict` is a global flag, taken by every one of these commands.
- Matroska `edit-inplace` / `EditInPlace`: a head with no room left moves the
  Tags, then the Chapters, the Info and the Tracks to the end of the Segment
  (RFC 9559 6.8) instead of refusing; it still refuses a file with no SeekHead
  or with bytes after its Segment.

### Added

- `demux` writes every stream in the file its codec's tools read, from an MP4
  as from a Matroska (the five codecs an existing Matroska demux changes for
  are under Breaking); written bare, none of them decoded.
  An MP4 track the remux cannot carry follows the remux's rule: the demux
  fails by its name (exit 1) unless `--skip-unsupported`
  (`DemuxOptions.SkipUnsupported`) drops it or `-t` names other tracks; a
  zero-length NAL unit no longer refuses an H.264/HEVC frame.
- `from-mp4` and `demux`: every track left out, a subtitle Matroska has no
  form for (TTML, CEA-608) or a non-media track included, is printed on
  stderr as `dropped track N (codec): reason` (N the file's own track ID),
  exit 0 as before; `--strict` (`Options.Strict`, `DemuxOptions.Strict`)
  fails them by name on any such track. The library reports each one through
  `Options.OnDrop` / `DemuxOptions.OnDrop` as a `mkv.DroppedTrack`
  (`mp4.DroppedTrack` is now that type). `tracks` and `probe` say per track
  whether `from-mp4` carries it: `to_matroska` and `to_matroska_refusal` in
  `-json` (`Track.Unsupported`), `[not carried to Matroska: reason]` in text.
- The same towards MP4 and HLS/CMAF: `to-mp4`, `to-hls` (and the ABR
  commands) and `serve` print every Matroska track they leave out - a
  subtitle the output has no form for, a secondary video track, an encrypted
  or unsupported codec - as `dropped track N (codec): reason` on stderr, exit
  0 as before, and take `--strict` (`Options.Strict`) to fail by name on any
  of them; so do `split`, `join`, `mux`, `merge` and the concatenations for
  the non-media tracks and subtitles they leave out, so the flag means the
  same everywhere. `tracks` and `probe` say per track, on a Matroska, whether each
  target carries it: `to_mp4` / `to_mp4_refusal` and `to_hls` /
  `to_hls_refusal` in `-json` (`mp4.TracksCarriage`), the reasons naming the
  flags. Fixed on the way: HLS reported an ASS track dropped with the MP4
  reason while carrying it as a WebVTT rendition.
- `from-mp4` carries MPEG-4 Part 2 (`mp4v` → `V_MPEG4/ISO/ASP`), TrueHD (`mlpa`
  → `A_TRUEHD`) and ALAC (`alac` → `A_ALAC`), as the mainstream muxer does;
  decoded, the Matroska matches the MP4 (checked with a decoder on real files).
  AC-4 still has no Matroska form.
- `demux` and `matroska.Demux` take an MP4/MOV: its tracks and blocks are those
  `from-mp4` would write, through the same formats (ADTS, Annex-B, Ogg), byte
  for byte what `ffmpeg -c copy` extracts; the tracks are named and selected
  (`-t`) by the MP4's own track IDs, the ones `tracks` lists; `mp4.WalkBlocks`
  hands a reader the remux's tracks before its blocks.
- `keyframes -walk` / `matroska.WithKeyframeWalk`: every keyframe from a pass
  over the Segment, for Cues that index only some of them. Listed from the
  Cues, the text form now says so on stderr.

### Fixed

- `demux` of Vorbis to Ogg: each page's granule counts the samples the decoder
  yields (block sizes and modes from the headers), less the last block's
  DiscardPadding, instead of a guess from the timestamps that cut the end
  short or ran past it.
- `diagnose` and `track-ends`: the bytes a walk skips past an unreadable element
  are no longer called damage (they include the sound media up to the next
  Cluster it could read); the message points to `salvage --dry-run` for the map.
- CLI: `to-mp4`, `from-mp4` and `to-hls` name `--skip-unsupported` where the
  refusal named `Options.SkipUnsupported`; `edit-inplace` refused for want of
  room names the `mkvgo edit` command that rewrites the file.
- HLS from a local MP4 (`serve`, `Open`): an audio segment is read ahead over
  its whole span like a video one; read run by run it broke the video's large
  disk reads (a full read of a 20-minute file: 11,217 reads of 79 KiB, 863 of
  1 MiB with the next entry).
- Linux read-ahead requests (`posix_fadvise` WILLNEED) go in pieces of the
  larger of the disk's `read_ahead_kb` and `max_sectors_kb`, the most the kernel
  reads per call: at the default 128 KiB read-ahead, 7,062 reads of 126 KiB for
  that full read became 863.
- HLS from a local Matroska (`serve`, `Open`): the scan a subtitle rendition
  makes of the clusters ahead of its window asks the disk for its range
  first, as a window's walk does, and from the Cues (or a subtitle index)
  reads no further ahead than the request needs; it read the blocks a few
  KiB at a time from scattered positions, and the pages it left split the
  next windows' read-ahead (a 2 GB MKV with three subtitle tracks, full read
  of every rendition on a fresh plan, HDD: 10,948 disk reads of 184 KiB at
  119 MB/s became 2,900 of 690 KiB at 176 MB/s, a sequential read of the file
  taking 2,300 of 875 KiB at 267; through a FUSE mount 17,400 of 115 KiB at
  107 MB/s became 8,700 of 230 KiB at 141 MB/s; random access unchanged on
  both).
- HLS segments read from a local file: the read-ahead covers the whole window
  across renditions, not the requested segment's own span. A player fetches a
  window's audio and video together; asked from its own first sample, the first
  request left the window to come off the disk in two runs (a fragmented MP4
  with its audio behind each fragment's video: 1,656 disk reads where a
  sequential read takes 1,104).

## [0.65.1] - 2026-11-07

### Fixed

- Matroska: the H.264 in-band scan walks the whole block again (at most 1,024
  NALs, 16 KiB of headers parsed), so a block holding both fields of a frame,
  its first one past 16 KiB, keeps its `field_order` (0.65.0 lost it).

## [0.65.0] - 2026-11-06

### Breaking

- Bytes served: HLS over CMAF adds the heaviest audio of a variant's group to
  its `BANDWIDTH`; a plan's DASH manifest lists the trick-mode set only when
  every segment has an I-frame, as the full pass does (it named fragments it
  then refused).
- `demux` to Ogg: a Vorbis page's granule is the end of its packet (it was the
  start), Opus's last one takes the end trim (DiscardPadding), and a packet
  past 65,025 bytes spans pages instead of failing.
- `Diagnose` with `DeepVerify` on a cut Segment of unknown size says
  `truncated` (tail), no longer `damaged` (body) with a `reindex --resync`
  remedy.
- `info` on an http(s) or s3 source leaves `truncated` out, as `probe` does:
  the check cost a request per top-level box of a fragmented MP4.
- The in-band scan of an H.264, HEVC or MPEG-2 track reads each sample's first
  16 KiB, as the MP4 one does: a header past it no longer settles `scan_type`.
- WebVTT: a BlockAddition's lines end at CR, LF or CRLF, so one written with
  CR alone keeps its cue identifier (served and extracted `.vtt`, `wvtt`).

### Fixed

- `demux`: a frame its codec's file cannot hold names the track, the block's
  time and `--raw`.

### Performance

- `demux` reuses one payload and one Annex-B buffer instead of allocating two
  per frame: half the time on a 1080p H.264 film.
- A CENC full pass reads each segment into a buffer its track keeps and
  encrypts it in place: about 40 % less time with `cbcs`.
- Writing a BlockGroup no longer copies its frame.

## [0.64.1] - 2026-11-05

### Security

- A BlockAdditional of unknown size crashed demux, remux, the HLS plan and
  `info -in-band` on the file; it is refused as damage, and so is a
  BlockMore or BlockAdditions of unknown size and a BlockGroup with more than
  64 BlockMore or 16 MiB of additions. Upgrade.
- WebVTT: a cue's settings or identifier taken from its BlockAddition could end
  its line and time cues of its own in the served or extracted `.vtt`; they
  stop at their first line end, and one holding `-->` is dropped.
- 32-bit builds: a NAL length past its frame crashed `demux` and keyframe
  extraction; it is refused.
- 32-bit builds: an audio CodecPrivate holding a `dec3` box of a crafted size
  crashed every HLS and DASH manifest of the file; the Atmos (JOC) check now
  reads only an E-AC-3 sample entry, so no other track announces Atmos either.
- 32-bit builds: an AV1 CodecPrivate OBU of a crafted size dropped the track's
  colour information or read a wrong one; the OBU is ignored.

## [0.64.0] - 2026-11-04

### Breaking

- JSON (CLI `-json`, WASM): an empty list is `[]` and an empty map `{}`, never
  `null`; the `cues[]` and `dropped_tracks[]` keys are snake_case
  (`time_ms`, `cluster_pos`, `id`, `reason`...). The Go API is unchanged.
- `Diagnose`: a Segment of unknown size (a streamed write) is a note in
  `Diagnosis.Notes`, no longer a finding; such a file is healthy.
- `--exit-damaged` also covers `info`, `probe`, `track-ends`,
  `salvage --dry-run` and `diagnose` (3 replaces its 1 on damage).
- `demux` writes each track as its codec's file (ADTS, Annex-B, Ogg, FLAC,
  `.sup`); `--raw` / `DemuxOptions.Raw` keeps the old bare payloads. See
  [cli.md](docs/cli.md#demux).
- Bytes served (inits, playlists, MPD): a cache keyed on them is stale.
  - Audio channels come from the stream (the AudioSpecificConfig, the AC-3 /
    E-AC-3 frame header, the init's sample entry), not the container; an
    E-AC-3 `dec3` lists its dependent substreams (a 7.1 says 8) and reads an
    AC-3 core as AC-3.
  - HLS masters: one audio group per codec when every language is in each,
    else one group; one `DEFAULT=YES` per group; unique `NAME`s; each
    variant's `BANDWIDTH` is its video and its group's heaviest audio track,
    the DASH video `bandwidth` the video alone. See
    [library.md](docs/library.md) (manifests).
  - New manifest attributes and elements (see Added): `VIDEO-RANGE`,
    `SUPPLEMENTAL-CODECS`, the CICP properties, `CHARACTERISTICS`, `Role` and
    `Accessibility`, Atmos (`CHANNELS="16/JOC"`, the `EC3_ExtensionType`
    property, the `dec3` extension), and the DASH trick-mode AdaptationSet
    (the video set gaining `id="1"`).
  - A Dolby Vision track in a Dolby sample entry is named `dvh1.PP.LL`
    (`dav1`, `dva1`) in `CODECS` / `codecs` (see Fixed).
  - Every audio and subtitle `EXT-X-MEDIA` carries `X-MKVGO-TRACK` (see Added).
  - An integrator caching masters, MPDs or inits built by an earlier version
    must rebuild them.

### Added

- `SourceCutShort` / `CutShortOf`: whether a source stops before its declared
  end, head-only (also the WASM probe's `truncated`).
- `Finding.Scope` (`head`, `body`, `tail`), the `mkv.Finding*` kind constants
  and `FindingKinds()`; `Track` on two more findings.
- `BlockReader.StoppedShort`, `TrackEndsReport.StoppedShort`.
- Manifests: `VIDEO-RANGE`, `SUPPLEMENTAL-CODECS` (Dolby Vision), CICP
  properties, `CHARACTERISTICS` / `Role` / `Accessibility`, Dolby Atmos (JOC)
  and a DASH trick-mode set over the I-frame fragments.
- HLS: `X-MKVGO-TRACK="<n>"` on every audio and subtitle `EXT-X-MEDIA`, the
  identifier the source file gives the track (Matroska TrackNumber, MP4 `tkhd`
  track_ID), to pair a rendition with its track without its `NAME`; the probe
  gives it as `Track.FileTrackID`. See [library.md](docs/library.md)
  (manifests).
- Block additions: `Block.Additions`, `Track.BlockAdditionMappings`,
  `Track.HDR10Plus`; every rewrite keeps them, WebVTT cue settings reach the
  converted WebVTT and `wvtt`.

### Changed

- Refusals carry their sentinel for `errors.Is` (`ErrNoKeyframeIndex`,
  `ErrNoVideo`, `ErrSourceTruncated`, `ErrDamagedRegion`, `ErrSourceChanged`);
  the messages change wording, match the sentinels.

### Fixed

- Cut and damaged files: `Diagnose` says `truncated` for a file cut between
  clusters, or one of unknown size cut inside a block; a cut tail is no longer
  damage; trailing tags or Voids after a streamed Segment are not a cut;
  `DeepVerify` on a streamed Segment reports its body damage; `Analyze`,
  `Validate` and `CueHealth` name the cut.
- Cue points past the end of a complete file are a corrupt index to reindex
  (`cues-stale`, `ErrNoKeyframeIndex`), not a cut source.
- MP4: `DeclaredSize`, `info` and `probe` walk every top-level box, as
  `Diagnose` does.
- A Dolby Vision track in a Dolby sample entry is named `dvh1.PP.LL` (`dav1`,
  `dva1`) in `CODECS`.
- Commands that read a whole local file refuse an http(s)/s3:// source with
  exit 2; documented JSON keys and `-json` list held to the code by a test.
- CLI: `demux`, `split`, `edit`, `edit-title`, `edit-track`, `remove-track`,
  `add-track`, `merge-subtitle`, `extract-subtitle`, `subtitle-index` and
  `extract-attachment` read flags placed before the source (`demux --raw f.mkv`
  opened a file named `--raw`).
- CLI: `info`, `probe`, `tracks`, `chapters`, `attachments`, `keyframes` and
  `tags` refuse an unknown flag with exit 2, before or after the file (it was
  opened as a file before it, ignored after it); global flags stay accepted
  anywhere.

## [0.63.0] - 2026-11-02

### Breaking

- Bytes written: a remux of a Matroska source that states a disposition flag
  as 0 (`FlagOriginal` 0, ...) leaves the element out, the spec default, and
  writes a flag set to 1 after `FlagForced`, where the source's own sat after
  its Video or Audio element; the media bytes are unchanged.

- `Track.ScanType`: an H.264 track whose SPS has `frame_mbs_only_flag` 0 and
  whose container states no `FlagInterlaced` now reads `""` (unknown), not
  `interlaced`: the flag only allows field coding, progressive streams carry
  it. A consumer that halved the frame rate on `interlaced` should treat `""`
  as unknown. `FlagInterlaced` 1 still gives `interlaced`.

- `Track.FieldOrder`: the Matroska `FieldOrder` values 9 and 14 now read `tb`
  and `bt`, the names the reference prober gives them (the first letter is
  the field stored first); mkvgo had them swapped. A `field_order` cached
  from an earlier release holds the swapped name: probe the file again.

### Fixed

- The disposition flags (`HearingImpaired`, `VisualImpaired`,
  `TextDescriptions`, `Original`, `Commentary`) are written from the `Track`
  fields: one set through the API is now in the output, one cleared is now
  left out (before, the source's elements were copied back as they were, and a
  flag set in code was lost).
- `Attachment.Description` (the Matroska `FileDescription`) is read, written
  when not empty, and kept by every operation that rewrites the attachments;
  before, a rewrite dropped it. `attachments --json` shows it.
- Hostile or damaged input, each refused or bounded where it panicked, looped
  or allocated what it declared: an `lpcm` entry shorter than its layout, a
  PCM table of 2^32-1 frames, a NAL, OBU or SEI length near 2 GiB and an HEVC
  syntax value past its range on a 32-bit build, an H.264 or HEVC crop past
  the picture, more than a million chapter atoms or simple tags, an MP4 sample past
  256 MiB, a VP9 superframe index short of its sample (`cenc`), a head element
  sized past the file (`edit-inplace`). `verify` hashes a sample as it reads
  it, no sample held whole.
- On-demand HLS of a Matroska source cut short after its head index declared
  segments past the file's end and a negative final duration, one cut inside
  a cluster lost the whole frames before the cut, and one cut inside the first
  block of a cluster served an empty last segment; the plan serves what the
  file holds, as the full pass does.
- `--keep-lang` and the wasm's `keepLangs` match the language the container
  resolves (a BCP 47 tag, the default English of a track stating none, `und`
  as written), where such tracks were dropped; a language matching no audio
  track is said.
- `probe --json` carries `truncated` for a local file, as `info --json` does.
- An AV1 sequence header with decoder model parameters keeps its colour
  config; a `BlockReader` given a TimecodeScale of 0 uses the default; MP3
  frame sizes are known under the Matroska CodecID.
- wasm: `codec_name` is written; the TypeScript types say the CICP colour
  fields are numbers and declare the analyze fields the JSON carries.
- `serve` prints the source without its query (a presigned URL's signature
  stayed on stdout).

### Added

- `matroska.ReadStream`: the forward-only reader on the facade; the CLI and the
  wasm go through the facade alone.
- The in-band option (`WithInBandColourFallback`, `mp4.Options.InBandColour`,
  always on in the remux and plan entry points) reads the first 16 samples of
  an H.264 track whose SPS allows field coding and gives it `interlaced` on
  proof - field-coded slices, frames whose fields have different picture order
  counts, or the picture timing SEI - with `FieldOrder` `tt`/`bb` when the
  samples agree; on MP4 too, and for an `avc3` record from the SPS the samples
  carry. An HEVC track whose hvcC states both source flags or neither is
  `interlaced` when its SPS codes every picture as a field, or, with the
  option, when its picture timing SEI says so. An MPEG-2 track gets its scan
  type from `progressive_sequence` and, with the option, from the picture
  coding extensions of its first samples. `reader.NewInBandScan` drives it off
  another sample table. See [docs/library.md](docs/library.md).

### Changed

- The 0.62.0 Deferred list no longer names the static release build, the full
  coverage and the TypeScript types, which that version shipped.

## [0.62.0] - 2026-10-31

### Breaking

- Bytes served: every `cenc` segment changes (see Security); grid-timed audio
  whose timecodes run ahead of the grid changes (experimental, see Fixed); the
  DefaultDuration audio `serve-growing` serves changes (see Fixed).
- CLI: bad usage exits 2 (was 1).
- A second `Options` value is refused (`mkv.ErrTooManyOptions`) instead of
  ignored; `httpfs.New`, `httpfs.Hybrid`, `mkvhttp.Handler` and
  `mkvhttp.FileHandler` panic on it where they are built, their `Checked`
  variants return it.
- `serve` on loopback answers 421 to a request naming another host: a local
  reverse proxy must send `Host: 127.0.0.1` ([cli.md](docs/cli.md#serve)).
- An output is written to `<dst>.mkvgo.tmp` and renamed into place, so a
  failure keeps the file already there; a second run writing the same output
  meanwhile is refused (`mkv.ErrOutputBusy`). Without `--sync`
  (`Options.SyncOutput`) a power loss can leave an empty file under the
  output's name ([cli.md](docs/cli.md)).
- The source's bytes, not its name, choose the MP4 or Matroska engine, and
  `mkvhttp.FileHandler`'s Content-Type.
- An encrypted plan's `SourceID` changes with its key.

### Security

- CENC `cenc`: from 0.56.0 to 0.61.0 an on-demand plan could reuse an IV
  between segments; fixed, every `cenc` segment changes: update if you use
  `cenc` ([library.md](docs/library.md#common-encryption-cenc)).

### Added

- CLI: global `--json`, `--exit-damaged` (exit 3 when a command acted on a
  damaged or incomplete source) and `--sync`; `analyze` reads MP4/MOV;
  `serve-growing` takes `serve`'s admission caps and `--memory-limit`.
- Library: `mp4.ForEachSample`, `mp4.ForEachBlock`, `mkv.ErrOutputBusy`,
  `mkv.ErrTooManyOptions`, `httpfs.NewChecked`, `httpfs.HybridChecked`,
  `mkvhttp.HandlerChecked`, `mkvhttp.FileHandlerChecked`.

### Changed

- CLI: Ctrl-C ends mkvgo as an interrupt, so a shell loop stops.
- `fingerprint` of an MP4 hashes its samples as it reads them: no temporary
  file, bounded memory, in wasm too.

### Fixed

- An incomplete file (it stops before the end it declares): `fingerprint`
  refuses it, MP4 as MKV (#2); `to-mp4`, `from-mp4`, `to-hls` convert it with
  a warning (`mp4.Options.OnTruncated`); `info` shows `Truncated`.
- Experimental: grid-timed audio whose timecodes run a frame ahead of the grid
  for a while no longer stays a frame late until the end; the segment where
  the delay ends absorbs it, so an on-demand segment is the full pass's bytes
  whatever order the segments are asked in. Playback of the absorbing segment
  is still being measured across players.
- `serve-growing` (`mp4.PlanGrowingHLS`): audio with a DefaultDuration (AAC,
  AC-3, E-AC-3) is timed on its grid like the full pass; it was timed by its
  millisecond timecodes, every audio segment differing from the full pass's.
- Two walks of a plan just built, looking for a track in the uncued regions at
  once, read what the other was recording about them (a data race under
  `-race`); every read of a region goes through the plan's lock.
- Review of v0.61.0: in-place edits, the Replace operations and hostile input
  (lacing, co64, quadratic reads) made safe; serving no longer stalls on a
  panic, a slow client, a slow read or a burst of I-frame playlist requests.

### Deferred

- The `mkv/ops` -> `mp4` dependency edge.
- The `js && wasm` tests in CI.

## [0.61.0] - 2026-10-24

### Breaking

- CENC on H.264/HEVC leaves parameter sets, SEI and slice headers clear, as
  ISO/IEC 23001-7 and CMAF ask; only slice data is encrypted. Every CENC
  H.264/HEVC segment changes: older ones still decrypt, but empty caches of
  them. Streams whose slice headers cannot be read (FMO, multi-layer HEVC) are
  refused. Rules and what was checked: [library.md](docs/library.md#common-encryption-cenc).

### Changed

- CLI: without `--cenc-iv`, `to-hls`, `to-abr`, `concat-hls` and `serve` draw
  a random IV and print it on stderr; `hls-segment`, `abr-segment` and
  `concat-segment` require it. The library still takes the IV it is given.

### Fixed

- A forged MP4 table count (stco, co64, stsc, stts, ctts, VP9 superframe
  index) no longer panics on 32-bit targets.

### Documentation

- README: head-only probing of an MKV without SeekHead or Cues reads every
  cluster header; a CENC key and IV must be unique per title.
- No package is described as stable or experimental any more: until 1.0 any
  package may change between minor versions, and Breaking names each change.
- Versions before 0.56.0 move to [changelog/](changelog/); entries are kept
  to a few lines, the detail lives in the docs.

## [0.60.0] - 2026-10-22

### Added

- `matroska.ErrMPEGTS` (and `mkv.ErrMPEGTS`): the error `mp4.ErrMPEGTS` is,
  now returned by every reader. An MPEG transport stream or a Blu-ray M2TS
  handed to the Matroska reader (`Open`, `OpenMeta`, `ReadStream`), to the
  content dispatch (`mkvgo.Diagnose`, `EditInPlace`) or to the repairs
  (`Reindex`, `Salvage`) is refused as "MPEG-TS detected: mkvgo does not read
  MPEG transport streams; remux the file to MP4 or Matroska first", whatever
  its name. They answered "ebml header: expected EBML header (0x1A45DFA3), got
  0x4740", or for an M2TS "invalid element ID: 5-octet VINT exceeds 4-octet
  limit", and the dispatch missed M2TS. It is not `ErrNotMatroska`, which sends
  a caller to the MP4 reader. The dispatch now asks three packets in a row, as
  the MP4 reader does, where it took two.
- `serve --memory-limit <MiB>` (off by default) sets the Go runtime's soft
  memory limit, as `GOMEMLIMIT` does. The window budget bounds the bytes kept,
  not the peak: the collector lets the heap grow to about twice what is live,
  kept windows included. At the budget plus 64 MiB, 100 random requests a
  second on a remote source peaked at 130 MB (MP4) and 142 MB (Matroska)
  instead of 137 and 191, at the same CPU per request.

### Fixed

- `hash` picks its engine from the file's first bytes, as `diagnose` does,
  not from its extension. A Matroska named `.mp4` is hashed instead of being
  told to remux, an MP4 named `.mkv` gets the MP4 answer (`to-mp4 --hash`)
  instead of "not Matroska/WebM", and an MPEG-TS or M2TS named `.mp4` is
